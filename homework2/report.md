## 解題說明

這次作業要做多項式的加法、乘法和代入計算，第二題再加上輸入和輸出。我把多項式的每一項存成「係數、指數」，例如 3x^2 + 5 就是 (3, 2) 和 (5, 0)。陣列裡的項目依指數由大到小排列。

新增一項時，如果已經有相同指數，就直接把係數加起來；加完變成 0 就刪掉那一項。這段放在 `AddTerm`，所以加法、乘法和讀取輸入都能用同一種方式處理同次方。

## 程式實作

第一題放在 [problem1.cpp](src/problem1.cpp)。`Add` 把另一個多項式的各項加進來，`Mult` 把兩邊的項目逐一相乘，`Eval` 把 x 代入後加總。程式中的 A = 3x^2 + 5、B = 2x - 5，設定 x = 2 來檢查結果。

第二題放在 [problem2.cpp](src/problem2.cpp)，加上 `>>` 和 `<<`。輸入格式是先輸入項數，再依序輸入每一項的係數和指數。例如 `3 2 2 -1 1 5 0` 會輸出 `P(x) = 2x^2 - x + 5`。

類別使用動態陣列存資料，所以也處理了複製建構、指定和解構，避免複製物件後共用同一個陣列。

## 效能分析

假設 A 有 n 項、B 有 m 項。新增一項時，程式會找位置，必要時移動原本的項目，最多要看過目前的所有項。`Add` 逐項加入 B，所以最差約是 O(m(n + m))；`Mult` 先做 n × m 次單項相乘，再逐一加入結果，最差約是 O((nm)^2)。這是目前程式的做法，並不是課本中用兩個位置同步走訪的加法寫法。

`Eval` 走訪 n 項，若把每次 `pow` 當成一次計算，時間是 O(n)。加法結果最多存 n + m 項，乘法結果最多存 nm 項。第二題讀入 k 項時，因為每項都要插入陣列，最差約 O(k^2)；輸出走訪一次，是 O(k)。

## 測試與驗證

第一題用 A = 3x^2 + 5、B = 2x - 5、x = 2 測試。執行後 A(2) = 17、B(2) = -1、(A + B)(2) = 16、(A * B)(2) = -17，跟手算相同。

第二題測了幾種輸入：

- `3 2 2 -1 1 5 0`：輸出 `P(x) = 2x^2 - x + 5`。
- `0`：輸出 `P(x) = 0`。
- `3 2 2 3 2 -5 0`：輸出 `P(x) = 5x^2 - 5`，兩個 x^2 項有合併。
- `1 2 -1`：顯示 `Invalid polynomial.`，負指數沒有被接受。

## 效能量測

用 g++ 的 `-O2` 編譯後，以程式計時比較 10、20、40 項的情況。測試資料的乘積沒有同次方，時間取多次執行的平均，單位是微秒：

10 項：Add 0.185、Mult 2.482、Eval 0.154。  
20 項：Add 0.397、Mult 25.146、Eval 0.262。  
40 項：Add 1.202、Mult 346.440、Eval 0.496。

乘法增加最快，因為每一項都要跟另一個多項式的各項相乘，結果插入陣列時還要找位置。

## 心得討論

這題讓我比較清楚多項式不能只把項目存在陣列，還要處理順序、同次方和係數變成 0 的情況。把這些處理集中在 `AddTerm` 之後，加法和乘法就比較容易寫。另外，使用動態陣列時要注意物件複製，不然兩個多項式可能指到同一塊記憶體。
